## Что нового

### v11.10 — починен аимлок, две кнопки везде, танцы сами, ускорение по Shift
- **Аимлок реально не работал — и вот почему.** Roblox пересчитывает
  `Camera.CFrame` в своём `BindToRenderStep` с приоритетом
  `Enum.RenderPriority.Camera`, а обычные коннекты `RenderStepped`
  выполняются **раньше** (`Default`). Наш доворот каждый кадр
  затирался игрой. Теперь аимлок вешается отдельным шагом с приоритетом
  `Camera + 1` — камера уже обновилась, и мы правим её последними.
  Это же объясняло жалобу «иду вперёд — тянет назад».
- **Две кнопки вместо простыни.**
  - Вкладка **AIM**: `КЛИЕНТ АЙМ (патрон в цель)` и `АИМЛОК (камера
    целится)` — большие кнопки с надписью ВКЛ/выкл. Аимлок работает,
    **пока держишь пушку** (зажата ЛКМ), в покое камера твоя.
  - Вкладка **ТАНЕЦ**: `ТАНЦЕВАТЬ` и `СПИН (крутишься)` — ровно две
    кнопки. Спин крутит модель на месте, работает вместе с танцем.
- **Танцы находятся сами.** Поиск запускается автоматически через
  секунду после старта (Animation-объекты + `require` модулей +
  то, что игра играет сама), найденное сразу попадает в список
  «Какой танец». Пассивный ловец каждые 4 с дополняет список. Кнопка
  «НАЙТИ ТАНЦЫ В ИГРЕ», поле для своего ID и лишние тумблеры/слайдеры
  (F7, покачивание, «ловить танцы», спринт с порогом и скоростью)
  **удалены**.
- **Убрано всё лишнее из меню** (по скриншотам): секция «Диагностика»
  (лог попаданий, диагностика патрона, лог ремоутов, глубокий лог 94
  ремоутов, лимит строк) и секция «Сканер» (4 кнопки/тумблер).
  Функции не выкинуты — вызываются из консоли:
  `getgenv().BS.ScanAll()`, `getgenv().BS.DeepScan()`,
  `getgenv().BS.ProbeWeapon()`.
- **Ускорение по клавише.** Держишь **Левый Shift** — скорость выше в
  N раз (слайдер 1.2–4, по умолчанию ×2). При отпускании и после
  респавна скорость возвращается сама.
- Меню собрано в функцию `buildGui()`: главный блок скрипта упёрся в
  лимит локальных переменных Lua (200).

### v11.8 — «бесконечные патроны» убраны, вместо них без кулдауна
- Проверено на живой игре: счётчик патронов живёт **на сервере**. Можно
  держать клиентский запас полным сколько угодно — сервер всё равно не
  засчитывает выстрел. Поэтому фича удалена целиком (код, настройка,
  элементы GUI): она только вводила в заблуждение.
- Вместо неё — **снятие кулдауна оружия**. В конфиге:
  `Config.Combat.WEAPON_COOLDOWN = 0.3`, `GUN_DRY_FIRE_GAP = 0.25`,
  `GUN_RECOIL_RECOVER = 0.25–0.5`. Клиентский код смотрит на метки
  готовности оружия (`ToolCooldown.ATTR`: `LuminolReadyAt`,
  `StunGunReadyAt`, …) и пока там время в будущем — не стреляет. Скрипт
  держит эти метки в прошлом, оружие всегда готово.
- Дополнительно — **обход кулдауна через время выстрела** (галочка, по
  умолчанию выкл). `FireWeapon(origin, dir, seed, data, time)`: сервер
  сверяет `time` с последним выстрелом и режет, если прошло меньше
  `WEAPON_COOLDOWN`. Скрипт сдвигает `time` вперёд на ползунок
  (0.1–2 с, по умолчанию 0.55), и сервер считает, что интервал выдержан.
- Кнопка «Показать метки кулдауна» печатает `[BS CD] оружие Pistol: …` —
  по строке видно, как игра на самом деле называет свои метки.

### v11.7 — аимлок не отстаёт на ходу + бесконечные патроны
- **Аимлок больше не тянет назад при ходьбе вперёд.** Причина: доворот
  камеры шёл плавным `LerpCFrame` каждый кадр, то есть камера постоянно
  недодоводила до цели. На ходу это выглядело как «отставание». Плюс
  сервер требует `Config.Combat.SHOT_ANGLE_SLACK_DEG = 3` — взгляд и
  патрон должны совпадать в пределах 3°, поэтому плавность тут не нужна.
  Теперь доворот **мгновенный по умолчанию**, а ползунок стал
  «Плавность доворота» 0–1 (1 = мгновенно, 0 = не доворачивать, между —
  плавно по времени, а не по кадрам).
- **Точка прицела пересчитывается в момент выстрела.** Раньше она
  считалась в начале кадра, пока ты шёл — камера успевала сдвинуться, и
  пуля уходила чуть позади цели. Теперь хук выстрела берёт позицию цели
  и пересчитывает направление от **фактической** точки вылета, которую
  игра передаёт аргументом №1.
- **Бесконечные патроны больше не гадают по имени атрибута.** Скрипт
  разбирает **все** числовые атрибуты оружия и ищет похожие на заряд
  (charge/ammo/mag/clip/bullet/shot), подставляя значение `Max*` или
  текущее + 20. Заодно обнуляет готовность (ReadyAt/Cooldown/Until — то,
  что хранит время в будущем), чтобы оружие всегда было готово.
  При смене оружия один раз печатается `[BS AMMO] атрибуты <Название>: …`
  — по этой строке видно, как игра на самом деле называет счётчик.
  Есть кнопка «Показать счётчик патронов».

### v11.6 — аимлок больше не слетает + спинт + глубокий лог ремоутов
- **Аимлок перестал сбрасываться при повороте камеры.** Причина была в
  лимите сервера `Config.Combat.SHOT_ANGLE_SLACK_DEG = 3`: пока угол
  между взглядом и патроном больше 3°, сервер отклоняет выстрел, поэтому
  раньше аимлок «замирал» на 3° и выглядел сломанным. Теперь:
  - **удержание цели** (`LockHold`, 0.6 с + пока зажат огонь): цель
    выбирается один раз и не меняется, пока смотришь на неё — раньше
    она выбиралась заново каждый кадр, и стоило чуть дёрнуть камеру,
    как захват слетал;
  - **смягчение по расстоянию**: коэффициент доворота падает с
    дистанцией (близко — мягко, далеко — быстро). Раньше один
    `LerpCFrame` на все дистанции перелетал с близкой цели на 50° за
    кадр;
  - «аимлок только если цель под прицелом» **удалён** — камера ведёт
    ту цель, которую реально выбрал клиент-айм.
- **Один список целей на всё.** Маркер в ESP, аимлок, точка прицела и
  подмена патрона берут цель из одного списка (отсортирован по
  расстоянию до центра экрана). Раньше у каждой части скрипта была своя
  логика выбора — можно было получить «маркер на одном, пуля в другом».
- **Спринт («спин» в бою).** Отдельная от танца настройка: модель
  доворачивается по направлению бега, поэтому в бою не уезжает боком.
  Порог бега и скорость доворота — слайдерами.
- **Глубокий лог ремоутов.** Галочка «Глубокий лог всех 94 ремоутов»:
  без ограничения по числу вызовов, с разбором вложенных таблиц
  (`dumpArgs`) **и с логом входящих событий** `[BS IN]` — то, что сервер
  шлёт сам: `CombatFeed`, `DamagePopup`, `DetectionFeed`, `EmotePlay`,
  `MatchResults`, `SuddenDeath`. Это то, чего раньше не было видно
  вообще, и по этому логу видно серверные правила.
- Лог `[BS DMG] CombatFeed` печатается раз в 10 событий, а не каждое
  (раньше за бой улетало 300+ строк одного и того же).

### v11.5 — триггер удалён (бот работал через раз)
- Убран **триггер** — правило «работаем только когда враг ПРЯМО в конусе
  12° (как автоатака игры)». Из-за него скрипт молчал, пока цель не
  попадала в узкий конус: выстрел в сторону/сбоку вообще не
  подменялся, и казалось, что бот не работает.
- Теперь цель выбирается **всегда**:
  1. та, что ближе к центру экрана (широкий конус ~35% высоты экрана);
  2. если под прицелом никого — ближайшая по расстоянию.
- Удалены: галочка «Только враг прямо по курсу», слайдеры «Угол
  триггера» и «Радиус триггера», вся математика градусов
  (`trigCos`/`bestTrig`) и запасной пиксельный конус. Секция
  «Триггер и прострел» переименована в «Прострел и дальность».
- Аимлок сохранён как был: камера доворачивается только на цель **под
  прицелом** (`AimLockNeedAim`) и только когда в руках оружие — чтобы
  камера не дёргалась сама.

### v11.4 — танец на ходьбе + спин
- **Танец играется самим скриптом.** Игровые эмоуты отменяются движением:
  начал идти — танец слетел. Поэтому анимация проигрывается напрямую
  через `Animator:LoadAnimation`: свой трек, `Looped = true`,
  приоритет `Action4`. Если походка играется на `Core` (127 — выше
  `Action4`), она опускается до `Action2` и возвращается при остановке
  танца. Итог: **персонаж идёт и танцует одновременно**.
- **Где берём танцы** (кнопка «НАЙТИ ТАНЦЫ В ИГРЕ», плюс автопоиск при
  запуске и пассивный ловец раз в 4 с):
  1. `Animation`-объекты в реплицируемых папках игры — их ассеты
     принадлежат игре, значит проиграются всегда;
  2. строки `rbxassetid://` в таблицах клиентских модулей (`require` +
     обход таблицы);
  3. анимации, которые игра **уже играет** на персонаже: если
     станцевать штатным эмоутом, его ID сам попадёт в список.
  Список печатается в консоль и попадает в выпадающий список GUI.
  Есть поле для своего ID на случай, если ассет чужой.
- **Спин и покачивание — без ассетов, работают всегда.** Это наш
  собственный поворот модели через `PivotTo` (дельтой угла, чтобы не
  сбивать направление взгляда). На время вращения `Humanoid.AutoRotate`
  ставится в `false` — иначе гуманоид каждый кадр доворачивает
  персонажа по вектору движения и спин не виден. Возвращается как было
  при выключении и после респавна.
- Спин и ассетный танец **можно включать вместе**. Слайдеры: скорость
  оборота 60–1080 °/с, размах покачивания 5–60°.
- **Клавиша F7** — включает/выключает танец, чтобы не лазить в GUI на
  ходу (галочка, чтобы отключить).
- Всё снимается в `G.BS_Stop()`: трек стоп, приоритеты и `AutoRotate`
  возвращаются, коннект клавиши отключается.

### v11.2 — триггер в градусах + точка прицеливания
- **Триггер считается в градусах, ровно как у игры.** В конфиге:
  `Config.UI.AUTO_ATTACK.CONE_DEG = 12` — игра сама стреляет по конусу
  12°. Теперь и мы считаем **угол между взглядом и целью** (а не
  пиксели на экране): если он ≤ угла триггера — работаем. Так аим и
  автоатака игры принимают одно и то же решение, и скрипт не доворачивает
  камеру туда, куда игра не выстрелит. Слайдер «Угол триггера (как у
  игры)» 1–60°, по умолчанию 12. Значение 0 возвращает старый режим
  «узкий конус на экране».
- **Точка прицеливания** (галочка + пикер цвета): маленькая метка
  там, куда **реально уходит патрон** (`bulletPreShot.pos`). Сразу
  видно, если точка уходит выше/ниже головы бегущего — по этому и
  подбирается опережение. Раньше прицеливание было «вслепую».
- **Подсказка по счётчику попаданий.** Каждые 25 выстрелов вместе с
  процентом попаданий печатается, что именно крутить дальше:
  - `<45%` → поднять скорость аимлока / угол триггера / снизить дальность;
  - `45–85%` → добавить опережение для бегущих (`AimLead = 0.15`);
  - `≥85%` → всё отлично, можно снизить опережение для стабильности.

### v11.1 — счётчик попаданий, бесконечные патроны, подсветка цели
- **Счёт попаданий.** Скрипт считает события `DamagePopup` /
  `CombatFeed` — их сервер шлёт, когда урон **реально прошёл**. Раз в
  25 выстрелов печатается:
  ```
  [BS DMG] выстрелов: 25 | урон получен: 11 | ~44%
  ```
  Это главная метрика: `0%` = выстрелы отклоняются сервером (угол
  взгляда больше `SHOT_ANGLE_SLACK_DEG = 3`), `100%` = попадает.
  При первом событии печатается формат аргументов
  (`[BS DMG] формат DamagePopup: ...`) — чтобы понять, чей это урон.
  Дополнительно: галочка «Лог попаданий (урон от сервера)» и кнопка
  «СЧЁТ: выстрелы / попадания» в AIM.
- **Бесконечные патроны** (галочка, вкл). У оружия атрибуты
  `Charges` / `MaxCharges` (пистолет 12/18, дробовик 8, снайпер 4) —
  каждые 0.25 с держим запас полным, перезарядка не прерывает
  стрельбу.
- **Подсветка текущей цели** (галочка + пикер цвета). Показывает, в
  кого именно наводится аим — иначе легко не понять, что скрипт
  выбрал соседа.
- **Обезоружен не значит цель.** Проверяется атрибут
  `DisarmedUntil` (модуль `Disarm`): пока действует, цель не
  выбирается — стрелять всё равно нечем.

### v11.0 — наводимся в СВОБОДНЫЕ (видимые) части тела
Галочка **«Целиться в свободные (видимые) части»** (вкл). Теперь
часть выбирается не просто «если ли она в персонаже», а **если до
неё есть прямая видимость**:

1. пробуем выбранную часть (по умолчанию `Head`) и `UpperTorso` /
   `Torso` / `LowerTorso` / `HumanoidRootPart`;
2. если они **перекрыты** (стена, ящик, укрытие) — идём по цепочке:
   **ноги** → **руки**;
3. берём первую часть, до которой луч от ствола не упирается;
4. если луч попал в **самого персонажа** (другая его часть, например
   плечо перед головой) — часть считается видимой.

Проверка идёт от ствола/камеры с исключением своего персонажа и
персонажа цели, максимум 9 кандидатов и **только для уже выбранной
цели** — на кадр это 1–3 рейкаста, не на каждого игрока.

Галочка «Аим по частям (голова → ноги → руки)» из v10.9 осталась —
это про наличие частей, новая — про видимость.

### v10.9 — приоритет частей тела при наведении
Новая галочка **«Аим по частям (голова → ноги → руки)»** (вкл).
Порядок выбора цели:

1. выбранная часть (по умолчанию `Head`) — **приоритет**;
2. если её нет — `UpperTorso` / `Torso` / `LowerTorso` /
   `HumanoidRootPart`;
3. если корпуса нет — **ноги** (`LeftUpperLeg`, `RightUpperLeg`,
   `LeftLowerLeg`, `RightLowerLeg`, `LeftLeg`, `RightLeg`,
   `LeftUpLeg`, `RightUpLeg`);
4. если нет ни корпуса, ни ног — **руки** (`LeftUpperArm`,
   `RightUpperArm`, `LeftLowerArm`, `RightLowerArm`, `Left Arm`,
   `Right Arm`, `LeftHand`, `RightHand`).

Часть считается доступной, только если она есть, это `BasePart`, у
неё есть родитель и она **не прозрачная** (скрытые прокси-части
игнорируются). Поддержаны и R15 (`UpperTorso`, `LeftUpperLeg`), и R6
(`Torso`, `Left Arm`), обе схемы сразу.

### v10.8 — аим для ломы + починены триггер, стены и прыжки
- **Аим для ломы** (новая галочка, вкл). По логу ремоутов
  `MeleeSwing`, `TrueFormMelee` и `StunFire` принимают **по одному
  Vector3 — направление удара**, значит удар проверяется так же, как
  выстрел. Направление заменяется на то же, куда наводит аимлок.
  Дальность удара — `Config.Combat.MELEE_RANGE = 17` (с запасом 18).
- **Триггер стал узким и реально рабочим.** Раньше он проверял широкий
  конус (35% высоты экрана) — срабатывал почти всегда. Теперь отдельный
  **узкий конус** 10% высоты экрана: срабатывает, только когда враг
  прямо по курсу. Слайдер «Радиус триггера» 0.03–0.40.
- **Аимлок не наводится сквозь стены** (новая галочка, вкл): если между
  камерой и целью стена, взгляд остаётся твоим.
- **Прыгающая цель больше не сбивает аимлок.** Две причины:
  1) камера смотрела в `Head`, а патрон летел в точку с опережением —

     расхождении больше `SHOT_ANGLE_SLACK_DEG = 3`. Теперь камера

  2) у прыгающего игрока вертикальная скорость ~25 студов/с, и
     опережение 0.08 с уводило точку на 2 студа выше головы. Смещение
     теперь **ограничено 2.5 студа**;
  3) если расхождение взгляда с целью больше 12°, доворот идёт

### v8.7 (главное — починка падений игры)

**Починена причина, из-за которой v8.6 роняла игру.** Скрипт вешал хук на
`game.__namecall` так:

```lua
local old = hookmetamethod(game, "__namecall", function(self, ...)
    return old(self, ...)   -- <-- здесь old ГЛОБАЛЬНАЯ (nil)!
end)
```

В Lua область видимости `local old` начинается **после** объявления. Поэтому
внутри функции справа `old` — не та переменная, что объявляется, а глобальная
(равная `nil`). Итог: на **каждый** вызов через `:` в игре (`FindFirstChild`,
`FireServer`, `wait`, ...) хук делал `attempt to call a nil value`. Отсюда сыпались
`GarlicController`, `ControlModule`, `CameraModule`, `InputLock`, `HotbarController`.

Что сделано:
- **forward-декларация** (`local old` + отдельное присвоение) вместо
  `local old = ...`;
- оригинал `__namecall` берётся из **сырой метатаблицы** (`getrawmetatable`);
- если оригинала нет — хук **не ставится вообще** (лучше без прострела, чем
  сломанная игра);
- `G.BS_Stop` корректно снимает хук;
- один общий хук `__namecall` обслуживает прострел, стамину и защиту от урона
  (отдельные `hookmetamethod(remote, "FireServer")` в этом исполнителе не
  работают — он принимает только имена метаметодов).

## Вкладка ESP

- 3D-коробки вокруг игроков;
- ник, дистанция, HP;
- цвета по ролям: вампир / хантер / игрок;
- Highlight + BillboardGui;
- роли только из надёжных источников: атрибут `player.Role`, роли из ремоутов
  (`RoleAssigned`, `RoleScan`, `RoleSeer`, `RoleToggle`), счётчики раунда.
  Догадки «по вещам» удалены — они ломали правдивость.

## Вкладка AIM

Только клиент-айм (подмена патрона) + прострел стен + диагностика.
Аимбота с доводкой камеры, круга прицела и бинда **нет**.

- **Клиент айм** — по умолчанию **ВКЛ**: аргументы `FireWeapon` подменяются так,
  чтобы пуля шла в выбранного противника (работает и через стены);
- прострел включён; дистанция подмены — 300, радиус метки — 160 px;
- **Диагностика патрона** — печатает в консоль сигнатуру `FireWeapon`
  (`[BS BULLET] подмена работает / сигнатура не распознана`).

## Защита от урона NPC / стамина

Оба выключены по умолчанию и живут в едином хуке `__namecall`
(`UseEnergy` — стамина, `TakeDamage` — урон).

## Запуск

Репозиторий **публичный**, поэтому достаточно одной строки — скрипт всегда
подтягивает свежую версию с GitHub:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/blegbot1/BloodyStreetESP/main/BloodyStreetESP.lua", true))()
```

Либо скопировать `BloodyStreetESP.lua` в редактор исполнителя целиком —
результат тот же.

`loader.lua` делает то же самое плюс защита от двойного запуска в течение
5 секунд.

Остановить скрипт: `G.BS_Stop()` (снимает хук `__namecall`, отключает все
коннекты и удаляет GUI/коробки).
