# Bloody Street ESP + клиент-айм

Версия **v10.5**. Проверено: `luac -p` — чисто, `luacheck` — 0 ошибок.

## Что нового

### v10.5 — автопроверка оружия (сама, без кнопок)
- Через 3 секунды после запуска скрипт **сам** читает модули игры
  (`Combat`, `Ballistics`, `Murder`, `Mystery`, `Loadout`, `Match`,
  `ToolCooldown`, `Roles`) через `require` и печатает в консоль
  **только** то, что относится к стрельбе: `Range`, `Distance`,
  `Spread`, `Damage`, `FireRate`, `Cooldown`, `Recoil`, `Ammo`,
  `Charges`, `Pierce` и т.п. — блок `[BS WEAPON]`.
- Там же печатается твоё оружие: имя, атрибуты (`Charges`,
  `MaxCharges`, `Variant`) и мировая позиция `Muzzle`.
- Кнопка «ПРОВЕРКА ОРУЖИЯ» в ESP (для ручного повтора), автозапуск
  отключается: `getgenv().BS.WeaponProbeOnStart = false`.

Зачем: по этим числам видно, почему выстрел не достаёт. Например у
дробовика может быть `Range = 90`, а мы стреляем на 404 студов — тогда
попадать невозможно при любой подмене.

### v10.4 — невидимый расширитель хитбокса (возвращён)
- К персонажу вешаются **прозрачные** части (`CanQuery = true`,
  `Transparency = 1`, `CanCollide = false`), приварены через
  `WeldConstraint` и следуют за телом. **Модель не меняется** — игроки
  выглядят как обычно, расширитель не видно.
- Две зоны: корпус (`2×5.2×2` × масштаб, с привязкой к
  `HumanoidRootPart` со смещением +0.3) и отдельно голова
  (`1.2×1.2×1.2` × масштаб).
- GUI, вкладка AIM, новая секция «Расширитель хитбокса»:
  - «Расширитель хитбокса (невидимый)» — вкл по умолчанию;
  - «Масштаб хитбокса» 1–5 (по умолчанию 1.6);
  - «Хитбокс и на голове» — вкл;
  - «Хитбокс только врагам» — вкл (роль по `player.Role`);
- обновление раз в 0.2 с, при выключении и в `G.BS_Stop()` части
  удаляются.

**Честно про ограничение:** части, созданные на клиенте, сервер не
получает. Если попадание в игре считает сервер (а раньше он
отклонял «выстрелы не по направлению взгляда»), расширитель ничего
не изменит. Проверяется просто: включил, крутанул масштаб — если
попадания не изменились, значит считает сервер.

### v10.3 — аимлок больше не мешает
Аимлок включается **только когда реально стреляешь**, больше не
дёргает камеру постоянно:

- **только с оружием в руках.** Проверяется наличие `Attachment`
  `Muzzle` или атрибута `Variant`. Взял дубинку или анализатор крови —
  аимлок молчит, камера полностью твоя (то, что тебя и бесило);
- **только цель под прицелом**, а не «ближайшая сзади» (новая метка
  `onScreen` в выборе цели);
- **только пока держишь огонь** — галочка (по умолчанию выключена:
  первый выстрел сразу улетает, без задержки на доворот);
- персонаж жив;
- проверка оружия кэшируется на 0.3 с.

### v10.2 — аимлок (камера целится в жертву)
Сервер проверяет, что выстрел уходит **туда, куда смотрит игрок**.
Направить патрон в цель, глядя в сторону, нельзя — выстрел
отклоняется («выстрел защищается»). Поэтому добавлен аимлок:

- галочка **«Аимлок (камера целится в жертву)»** — камера
  доворачивается на ту же цель, по которой идёт подмена патрона;
- слайдер **«Скорость доворота камеры»**: 0 — мгновенно, 14 (по
  умолчанию) — быстро, 40 — мягко;
- позиция камеры не меняется (вид от третьего лица остаётся),
  меняется только направление взгляда;
- патрон по-прежнему идёт через клиент айм (подмена аргументов
  `FireWeapon`).

### v8.7 (главное — починка падений игры)

**Починена причина, из-за которой v8.6 роняла игру.** Скрипт вешал хук на
`game.__namecall` так:

```lua
local old = hookmetamethod(game, "__namecall", function(self, ...)
    return old(self, ...)   -- <-- здесь old ГЛОБАЛЬНАЯ (nil)!
end)
```

В Lua область видимости `local old` начинается **после** объявления. Поэтому
внутри функции справа `old` — не та переменная, что объявляется, а глобальная
(равная `nil`). Итог: на **каждый** вызов через `:` в игре (`FindFirstChild`,
`FireServer`, `wait`, ...) хук делал `attempt to call a nil value`. Отсюда сыпались
`GarlicController`, `ControlModule`, `CameraModule`, `InputLock`, `HotbarController`.

Что сделано:
- **forward-декларация** (`local old` + отдельное присвоение) вместо
  `local old = ...`;
- оригинал `__namecall` берётся из **сырой метатаблицы** (`getrawmetatable`);
- если оригинала нет — хук **не ставится вообще** (лучше без прострела, чем
  сломанная игра);
- `G.BS_Stop` корректно снимает хук;
- один общий хук `__namecall` обслуживает прострел, стамину и защиту от урона
  (отдельные `hookmetamethod(remote, "FireServer")` в этом исполнителе не
  работают — он принимает только имена метаметодов).

## Вкладка ESP

- 3D-коробки вокруг игроков;
- ник, дистанция, HP;
- цвета по ролям: вампир / хантер / игрок;
- Highlight + BillboardGui;
- роли только из надёжных источников: атрибут `player.Role`, роли из ремоутов
  (`RoleAssigned`, `RoleScan`, `RoleSeer`, `RoleToggle`), счётчики раунда.
  Догадки «по вещам» удалены — они ломали правдивость.

## Вкладка AIM

Только клиент-айм (подмена патрона) + прострел стен + диагностика.
Аимбота с доводкой камеры, круга прицела и бинда **нет**.

- **Клиент айм** — по умолчанию **ВКЛ**: аргументы `FireWeapon` подменяются так,
  чтобы пуля шла в выбранного противника (работает и через стены);
- прострел включён; дистанция подмены — 300, радиус метки — 160 px;
- **Диагностика патрона** — печатает в консоль сигнатуру `FireWeapon`
  (`[BS BULLET] подмена работает / сигнатура не распознана`).

## Защита от урона NPC / стамина

Оба выключены по умолчанию и живут в едином хуке `__namecall`
(`UseEnergy` — стамина, `TakeDamage` — урон).

## Запуск

Репозиторий **публичный**, поэтому достаточно одной строки — скрипт всегда
подтягивает свежую версию с GitHub:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/blegbot1/BloodyStreetESP/main/BloodyStreetESP.lua", true))()
```

Либо скопировать `BloodyStreetESP.lua` в редактор исполнителя целиком —
результат тот же.

`loader.lua` делает то же самое плюс защита от двойного запуска в течение
5 секунд.

Остановить скрипт: `G.BS_Stop()` (снимает хук `__namecall`, отключает все
коннекты и удаляет GUI/коробки).
