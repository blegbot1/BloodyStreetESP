v11.16: ускорение в прыжке + танец не сбрасывается на ходу

1) УСКОРЕНИЕ В ПРЫЖКЕ (по просьбе).
При каждом прыжке:
- WalkSpeed умножается на G.BS.JumpBoostMul (по умолчанию 1.7)
  на G.BS.JumpBoostTime (0.8 с);
- добавляется горизонтальный импульс по направлению движения,
  чтобы рывок был виден сразу, а не только в цифре скорости.
Работает вместе с ускорением по Левому Shift и без него.
В GUI (вкладка ESP, секция «Скорость») добавлены:
- тумблер «Ускорение в прыжке» (по умолчанию включён);
- ползунок «Множитель прыжка» (1.1..3.0, шаг 0.1).
Повторный прыжок отменяет старый таймер через sequence, поэтому
бусты не складываются бесконечно.

2) ТАНЕЦ БОЛЬШЕ НЕ СБРАСЫВАЕТСЯ ПРИ ХОДЬБЕ.
Раньше эмоут EmotePlay:FireServer("emote_dance") повторялся каждые
2.5 с. Игра обрывала эмоут при движении, поэтому танец дёргался и
«отваливался» на ходу.
Теперь:
- ID анимации эмоута перехватывается хуком LoadAnimation сразу
  после EmotePlay (ловушка dance.pendingEmote), а также из
  EmoteSetSlots (dance.pairIds) и из новых треков Animator
  (dance.captureId) — на случай, если хук не сработал;
- известный ID играется локальной зацикленной анимацией на
  Action4: ходьба её не отменяет;
- раз в секунду походка, пересозданная на Core, снова опускается
  до Action2, чтобы не перебивать танец;
- если игра всё-таки остановит трек, событие Stopped поднимает
  его через 0.1 с;
- если ID ещё неизвестен, эмоут повторяется раз в 1.2 с (быстрее,
  чем раньше), пока ID не поймается;
- штатный эмоут всё равно отправляется один раз, чтобы танец
  видели другие игроки.

3) МЕЛОЧИ.
- stopDance/playId обнуляют dance.track ДО Stop, чтобы событие
  Stopped не приняло намеренную остановку за случайный обрыв.
- restoreLowered очищает __bsOldPrio, иначе трек нельзя было
  опустить повторно после восстановления приоритета.
- Комментарий у повтора эмоута обновлён.

Версия помечена v11.16.
Проверено: luac -p чисто, luacheck 0 ошибок
(5 старых безобидных предупреждений: math.clamp и unused args).
